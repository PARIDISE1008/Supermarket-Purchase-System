### 1. Redis 缓存接入

为系统添加 Redis 缓存层，使用 Spring Cache 抽象（`@Cacheable` / `@CacheEvict`）+ Redis 作为缓存存储，对前端实际调用的**分页列表查询**（`search()`）进行缓存，写操作时通过 `allEntries = true` 清除该实体全部缓存。

**第一轮（getById）→ 发现未命中**：
- 初始将 `@Cacheable` 加在 `getById` 上，但前端所有列表页均直接调用 `search()` 获取数据，编辑弹窗复用表格行数据，`getById` 从未被触发
- `redis-cli monitor` 只看到 `DEL`（@CacheEvict），没有 `GET`/`SET`

**第二轮（search）→ 匹配前端流量**：
- 将 `@Cacheable` 从 `getById` 迁移到 `search()`，key 为复合参数（名称、筛选条件、页码、每页数）
- 写方法（add/update/delete/batchImport/approve/reject）全部改为 `allEntries = true` 清除整个命名空间
- 保留 `getById` 的 `@Cacheable` 不变，后续详情页可用

**设计原则**：
- 缓存前端实际调用的 `search()` 分页查询，key 包含全部搜索参数
- 写操作统一用 `allEntries = true` 清除该实体全部缓存
- 不缓存 login（安全敏感）、采购提交（高频写）
- 全局 TTL 10 分钟，防止缓存雪崩

### 3. 缓存 key 设计

| 实体 | 缓存 key 示例 |
|------|--------------|
| goods | `goods::search:苹果:5:1:10` → 搜索"苹果"+供应商5，第1页10条 |
| employees | `employees::search:~:~:1:10` → 无筛选，第1页10条（~表示null） |
| members | `members::search:~:2:2:20` → 会员等级2，第2页20条 |
| suppliers | `suppliers::search:华为:1:10` → 搜索"华为"，第1页10条 |

### 4. 失效策略

任何写操作（add/update/delete/batchImport/approve/reject）均使用 `@CacheEvict(allEntries = true)` 清除该实体**全部**缓存，下一次 `search()` 重新查 DB 并写入 Redis。设计考量：

- 分页列表的数据变化无法精确定位到单个 key（新增/删除影响所有页码）
- `allEntries` 简单可靠，写操作频率低，对性能影响可忽略
- 配合 TTL 10 分钟兜底，避免缓存长期不一致

### 5. 验证结果

`redis-cli monitor` 输出确认：

```
GET "employees::search:~:~:1:1"     ← 首次请求未命中
SET "employees::search:~:~:1:1" ... ← 写入缓存 (PX 600000)
GET "suppliers::search::1:10"       ← 列表页翻页
SET "suppliers::search::1:10" ...   ← 写入缓存
DEL "goods::search:~:~:1:10"        ← 写操作触发 allEntries 清空
```

- ✅ Redis 连通：`HELLO "3"`（Lettuce 握手）
- ✅ `@Cacheable` 命中：GET → 未命中 → SET 写入
- ✅ `@CacheEvict` 生效：DEL 清空整个命名空间
- ✅ 序列化正确：Jackson 类型信息完整保留（BigDecimal、LocalDateTime 等）

### 6. 序列化方案

RedisTemplate 和 CacheManager 统一使用 Jackson2JsonRedisSerializer：
- 启用 Jackson 默认类型（`DefaultTyping.NON_FINAL`）以支持多态反序列化
- 注册 `JavaTimeModule` 支持 `LocalDateTime` 序列化
- 禁止时间戳输出（`WRITE_DATES_AS_TIMESTAMPS = false`）

## 技术要点

- **零业务入侵**：只加注解，不改一行业务逻辑代码
- **Spring Cache 降级**：Redis 不可用时，可通过 `spring.cache.type=none` 一键关闭缓存
- **缓存粒度**：按实体类型分 namespace（goods/employees/members/suppliers），避免 key 冲突
- **allEntries 适用场景**：写操作低频、数据量小、缓存 key 组合多的场景下，清除全部缓存比逐 key 管理更简洁可靠
