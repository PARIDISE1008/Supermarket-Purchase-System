## 四、员工登录修复（两轮）

### 第一轮：INSERT 缺失 is_approved 列
- EmployeeMapper.xml: `insert` 和 `batchInsert` SQL 补上 `is_approved` 列
- EmployeeServiceImpl.java: `batchImport()` 补上 `emp.setIsApproved(1)`
- 根因：DB `is_approved DEFAULT 0`，但 INSERT 没写该列 → 新增员工 is_approved=0 → 登录被拒

### 第二轮："已审批"Tab 错误显示待审批员工
- EmployeeMapper.xml: `selectPage` 和 `count` 加 `AND is_approved = 1`
- 根因：selectPage 返回全部未删除员工，管理员误以为已通过审批
- Employee.vue: `handleApprove`/`handleReject` 的 `catch {}` → `catch (err) { ElMessage.error }`

## 六、采购弹窗实时计算重构

### 删除
- 深 `watch(purchaseItems, ..., { deep: true })`（自我触发、无防抖、无边界处理）

### 替换为事件驱动 + 防抖

```js
function calcItem(item) {  // 纯函数，返回实付金额
  const qty = Number(item.quantity) || 0
  const price = Number(item.unitPrice) || 0
  const discount = Math.min(100, Math.max(0, Number(item.discount) || 0))
  return (qty * price * (1 - discount / 100)).toFixed(2)
}

function debouncedRecalc() {  // 200ms 防抖
  clearTimeout(recalcTimer)
  recalcTimer = setTimeout(() => {
    purchaseItems.value.forEach(i => { i.subTotal = calcItem(i) })
  }, 200)
}
```

### 新增
- 折扣列：每商品 `discount` 字段，`el-input-number :min="0" :max="100"`
- `subtotalAmount` computed：折前小计 `sum(qty × price)`
- `discountAmount` computed：优惠 `subtotalAmount - totalAmount`
- `totalAmount` computed：实付 `sum(calcItem(i))`
- 汇总区：总数量 | 小计 | 优惠 | **实付**
- `cleanupCreate` / `onUnmounted` 清理 `recalcTimer`
